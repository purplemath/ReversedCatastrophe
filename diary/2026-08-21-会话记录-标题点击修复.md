以下为第一层修复时的原始记录（保留供参考）：

**根因**：`title_screen.gd` 根节点（及多处全屏控件）用的是
`set_anchors_preset(Control.PRESET_FULL_RECT)`——该方法**只写锚点、不写偏移**，
而且 Control 加入场景树时没有父级 resize 事件来触发按锚点重算，导致这些控件
**实际矩形一直是 0×0**。

后果链条：
- 渲染不受父级矩形裁剪 → 按钮照常画出来，界面"看起来正常"（其实菜单一直
  挤在左上角、水面/天空渐变/波浪全是 0 尺寸不渲染，从未有人发现）
- **GUI 鼠标命中测试从根控件矩形逐层裁剪 → 根 0×0 → 任何鼠标事件都命中不到
  任何按钮** → "点击无反应"
- 键盘之所以（推测）能用：grab_focus + 焦点导航不依赖矩形命中

**为何旧测试没发现**：`title_pick_test` 是**直接调用** `_open_slot_picker("new")`，
从未走过 `Button.pressed` 信号 → GUI 事件路由 → 方法 这条真实链路。

## 四、工程坑新增（重要）

8. **`set_anchors_preset()` 只设锚点不设偏移**：运行时代码创建的 Control 若
   用它设全屏，加入树后没有父 resize 事件就永远 0×0——渲染正常但 GUI 鼠标
   命中全灭（静默坏损）。**运行时建 UI 一律用 `set_anchors_and_offsets_preset()`**；
   .tscn 里保存的锚点带偏移数据，不受影响
9. 测试 GUI 点击链路必须注入真实鼠标事件（push_input 移动+按下+释放），
   不能只直接调方法；headless 下用 1280×720 的 SubViewport 承载，
