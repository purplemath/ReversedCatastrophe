## 项目速览

- Godot 4.5 + GDScript，2D 横版洪水题材，核心机制：时间回溯（长按R）+ 救人变强 + 救灾知识卡
- 设计文档：`D:\Desktop\逃生星座出口\《逆转的天灾》机制整理v0.3.xlsx`（读取工具：`python tools/read_xlsx.py <路径>`）
- 关卡数据驱动：JSON schema 由 `Town.builtin_layout()` 定义，编辑器与游戏共用
- 主场景：标题 → 游戏（main.tscn）/ 地图编辑器（editor.tscn）

## 常用命令

```bash
GODOT="/d/Program Files/Godot_v4.5-stable_win64.exe/Godot_v4.5-stable_win64.exe"
"$GODOT" --headless --import --path .                       # 新增资源/类后先导入
"$GODOT" --headless --path . res://test/integration_test.tscn --quit-after 8000   # 主集成测试
"$GODOT" --headless --path . res://test/editor_test.tscn --quit-after 3000        # 编辑器测试
```

注意：headless 空转帧率(~144fps)≈物理帧率(60)的2.4倍，`--quit-after` 要给物理帧数的 2.5 倍以上，否则测试会被提前掐断。

## 核心设计决策（勿轻易推翻）

- 死亡处理：浮出水面=存档点；溺死=回存档点满状态复活（不是回溯3秒）；复活清空回溯历史
- 回溯系统：`rewindables` 分组 + capture_state/restore_state 鸭子接口；木箱倒带时 freeze
- 取舍机制（本轮新增）：幸存者为 LOST 状态后不再被回溯复活（命运锁定）
- 知识卡：`data/knowledge_cards.json` 纯数据，每救一人解锁一张
- 编辑器关卡存档：`user://custom_level.json`

### 本轮实现要点（给后续会话的提示）

- 平台乘载：Godot 4.5 没有 `platform_velocity` 属性，AnimatableBody2D 自动乘载不可靠；
  采用 move_and_slide 后手动叠加 `current_velocity * delta`（player.gd），MovingDebris 每帧记录 current_velocity
- `Dictionary.get(key, default)` 的 default 是提前求值的——不要在 default 里写可能不存在的键访问
- 水位倒计时逻辑在 GameState._physics_process（自动加载的物理帧），暂停时自动冻结
- LOST 幸存者的 restore_state 有命运锁（state==LOST 直接 return），回溯不能复活失落者
- 首次救援触发 3 行对白（还有被困者时），后续救援只弹卡；全部解决后播放分支结局对白
- 测试三件套：integration_test（完美路线）/ loss_test（失落路线）/ editor_test（数据与编辑器）
